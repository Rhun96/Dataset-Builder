# HANDOFF — Dataset Builder v2 (AI Trainer Workbench)

Дата среза: 2026-11-03. Пишу для себя-будущего: здесь всё, чтобы продолжить без потери контекста.

## 1. Что за проект

Десктоп-инструмент AI-тренера: из сырого пула (XLSX/CSV/JSON/JSONL/ODS) быстро собрать
правильную воспроизводимую выборку и выгрузить её пакетом (dataset + manifest + отчёт).
Стек: Python 3.11+, PySide6 + PySide6-Fluent-Widgets, SQLite, всё локально, без сети и LLM.

Граница с LocalReviewer (решает пользователь, код/визуал НЕ копируем):
Dataset Builder готовит выборку ДО импорта. LocalReviewer размечает ПОСЛЕ.
Связь только файлами. Ядро (`core/`) вообще не импортирует Qt — проверяется тестом.

Папка проекта: `E:\Проект для OpenCode\Конструктор датасета v2`
Репозиторий: https://github.com/Rhun96/Dataset-Builder (main, пуш из локалки руками автора или агентом по просьбе)
Рабочая папка приложения: `Документы\DatasetBuilderV2` (БД `workspace.sqlite`, экспорт, бэкапы).
Демо-данные: `demo_data/` (demo.csv, demo_ru.csv — с `;` для русского Excel, demo.jsonl).
Тестовые БЗ на рабочем столе: `БЗ_старая.md`, `БЗ_новая.md`.

## 2. Как запускать

- `run_app.bat` — запуск GUI (актуальный код). `start.bat` — самопроверка (тесты + демо-разведка).
- `build_exe.bat` — сборка exe ТОЛЬКО по просьбе пользователя (договорённость!).
  Результат: `dist\DatasetBuilderV2\DatasetBuilderV2.exe` (~78 МБ).
- Проверка: `py -3 -m pytest -q` (сейчас 79 тестов), `py -3 -m ruff check .`
- ВАЖНО: тесты/команды запускать с `workdir` = корень проекта, иначе pytest лезет в C:\WINDOWS.
- `run_gui.py` — точка входа для PyInstaller. `DatasetBuilder.spec` — one-dir сборка.

## 3. Протокол работы с пользователем (обязателен)

- Я (агент) делаю консоль/тесты/код сам. От пользователя — только функционал и визуал.
- Каждый этап заканчивается чекпоинтом: что нажать + что прислать (скрины/текст результата).
- Без подтверждения чекпоинта дальше не идём (пользователь сам это требовал, потом смягчили, но суть та же).
- bat = свежий код всегда. exe обновляется ТОЛЬКО когда пользователь прямо скажет.
- Отвечать коротко, по делу, на русском, без воды и эмодзи.
- Пользователь тестирует двойным кликом, команды в консоль не даёт (были инциденты: запускал pytest из system32).
- Если пользователь правит код сам — попросить сказать, чтобы не затереть друг друга.
- Не выдумывать URL и факты; сомневаешься — проверь код/тесты, а не память.

## 4. Архитектура (файлы)

- `core/normalize.py` — нормализация: NFKC → NBSP→пробел → схлопнуть → strip → casefold → ё→е. Отпечаток sha1.
- `core/source_reader.py` — потоковое чтение 5 форматов, авторазделитель СМОТРИТ НА СТРОКУ ЗАГОЛОВКА (не первую строку файла!), коды ошибок Excel → пусто+счётчик, отмена/прогресс.
- `core/roles.py` — generic-роли: main_text, response_text, ext_id, group, topic, comment, kb_ref(source→«Источник»), extra, ignore + custom:* (до 64 символов). Без привязки к LocalReviewer.
- `core/pool_import.py` — загрузка пула в SQLite (оригиналы целы, нормы — для отбора).
- `core/filter_service.py` — фильтры eq/ne/in/notin/missing/notmissing/contains/gt/lt + build_items_union (новизна).
- `core/requirements.py` — BuildProfile + profile_to_dict/from_dict. SEED называется «Вариант выборки» (пользователь ненавидит слово «зерно»).
- `core/coverage_service.py` — покрытие с дефицитом, без общих баллов. Учитывает фильтры И жёсткие исключения.
- `core/sampling_service.py` — отбор (random/quota/stratified/mixed), ALGO_VERSION=3, причины включения сразу, лимит доли источника, новизна (exclude/min_new/keep), закреплённое, разнообразие (Жаккар, порог), редкость.
- `core/variant_service.py` — N вариантов одной конфигурации (seed+1..N), сводка без интегрального балла.
- `core/replace_service.py`, `core/compare_service.py` — замена из той же ячейки новой ревизией; сравнение (добавлено/исключено/сохранено + сдвиги).
- `core/pool_profile.py` — сводка, распределения, топ, anomalies(), pool_overview(), fill_rate(), per-source разбор.
- `core/knowledge_reader.py` + `core/knowledge_diff_service.py` — txt/md/html/docx по разделам, added/removed/changed + render_html было/стало с подсветкой слов.
- `core/related_cases_service.py` — кандидаты на перепроверку (source/phrase/words), transfer_to_build.
- `core/pool_import.py`, `core/field_roles.py` — НЕТ такого; маппинг живёт в UI + validate_mapping.
- `core/quota_presets.py` — proportional/uniform. `core/advisor.py` — авто-подбор с объяснением (редкие целиком + пропорция + дедуп).
- `core/external_import.py` — импорт готового набора: сначала ext_id, потом fingerprint.
- `core/export/package_exporter.py` — dataset XLSX (шапка закреплена, автофильтр, ширины, formula-guard "'"), CSV `;`, JSONL, manifest.json, coverage.csv, selection_report.txt.
- `storage/database.py` — SCHEMA_VERSION=8, миграции 1..8 (маппинг, пул, сборки, pinned, БЗ, req_profile, note, in_pool+вьюхи pool_candidate/pool_dim). backup_now() + авто-бэкап перед миграциями (backups/, держать 10).
- `ui/` — app.py (FluentWindow + центрирование + DPI PassThrough + native_frame fallback + pad_below_titlebar), sources/profile/requirements/builds/knowledge/settings/import_dialog/proposal_dialog/pool_dialog, workers.py (фоновый импорт), theme.py (янтарный акцент #F5A524, графит #14161A, светлая #F2F4F7, wrap_in_scroll, pad_below_titlebar), donut.py, stepper.py — УДАЛЁН (см. проблемы).
- `tools/` — inspect_pool.py (разведка пула), make_demo.py.

Ключевые инварианты:
- Сборки иммутабельны: правки = новая ревизия. Удаление сборки показывает связи с профилями.
- Manifest содержит: вариант, algo-версию, конфиг, sha256 источников, покрытие, причины каждой записи.

## 5. Что сделано (по-крупному, в порядке работы)

1. Каркас + чтение + нормализация (NFKC→casefold→ё→е) + SQLite + inspect_pool + start.bat.
2. Generic-роли + custom:* + загрузка пула (оригиналы/нормы/отпечатки).
3. Экран «Источники»: файл→листы/шапка/кодировка/разделитель→роли→загрузка в фоне. Автоопределение разделителя по строке заголовка.
4. Профиль пула: сводка, дашборд-карточки, донат долей, топ-бары, аномалии, просмотр по источникам (комбо «Все/один»).
5. Требования: размер, «Вариант выборки» с подсказкой, режимы (random/quota/stratified/mixed), квоты (в т.ч. комбинированные «измерение × измерение»), фильтры 8 операторов, быстрый набор «колонка → значения с counts → добавить», живой счётчик «Подходящих записей», пресеты (пропорционально/равномерно/сколько есть/авто-подбор с объяснением), новизна (исключить/минимум новых/сохранить), лимит доли источника, разнообразие (Жаккар), редкие первыми, сохранённые именованные профили (сохранение/загрузка/удаление, авто-включение продвинутого режима).
6. Покрытие с дефицитом по ячейкам, русскими подписями («Группа / категория», «не менее/ровно/%»).
7. Сборка и экспорт: состав с причинами, предпроверки (готово/с предупреждениями/заблокировано), закрепить/заменить/исключить, варианты, сравнение, удаление с каскадом, импорт готового набора (маппинг-диалог), выгрузка пакета.
8. Изменения БЗ: два состояния (md/txt/html/docx) → diff → «что изменилось» с подсветкой слов → кандидаты на перепроверку (источник/фраза/слова) → в сборку.
9. Визуал: Fluent-навигация с нумерованными шагами (1·Профиль, 2·Требования, 3·Сборка), янтарный акцент #F5A524 (qconfig.themeColor, save=False — чужой конфиг не трогаем), графитовый фон #14161A, светлая #F2F4F7, тёмная/светлая/системная тема с запоминанием, явная сетка таблиц, белые статусы (ок/предупреждение/блок), окно центрируется + DPI PassThrough + запасной нативный заголовок, все экраны в скролле (окно свободно ресайзится), классический диалог импорта (Fluent-комбо в нативном диалоге не рисовались — заменены на Qt).
10. Выбор пулов: галочки «В пуле» + диалог «Источники…» в Требованиях; пул = вьюхи pool_candidate/pool_dim.
11. Бэкап БД: авто-копия перед миграциями (SQLite backup API, ротация 10), кнопка в Настройках.
12. NFR проверены на синтетике 100к: импорт 12.8 c, сводка 0.84 c, распределение 0.49 c, сборка 500 из 100к за 1.17 c.

## 6. Грабли, на которые уже наступали (читать перед правками!)

- Тесты править/писать ТОЛЬКО через файлы, записанные целиком (write), либо точечные edit с уникальным контекстом. НИКАКИХ однострочных правок «для красоты» и НИКАКИХ heredoc-однострочников с \n в shell — они склеивают строки и ломают синтаксис. Правило: видел edit с old/new, отличающимися только пробелами/переносами — НЕ ДЕЛАЙ.
- Fluent ComboBox: addItem(text, userData) — ВТОРОЙ позиционный аргумент это ИКОНКА, userData только именованным! currentData() при пустом userData возвращает текст. Проверять через setCurrentIndex/findData.
- Fluent TableWidget() — конструктор БЕЗ размеров (TableWidget(rows, cols) падает). Сначала создать, потом setColumnCount/RowCount.
- QTableWidgetItem отдельно импортируется из PySide6 — replaceAll QTableWidget→Fluent ломает его в QQTableWidgetItem. Проверяй grep'ом.
- Неинициализированные Fluent-комбобоксы по умолчанию index 0 — ок, но currentData() до заполнения = None: везде проверки `if dim`.
- wrap_in_scroll: layout переезжает через inner.setLayout(widget.layout()) — работает, но вызывать ОДИН раз в конце __init__. Не вызывать дважды (вложенные скроллы).
- QSS не красит QScrollArea viewport (проверено попиксельно) — только кодом через палитру + inline-стиль inner (см. paint_scroll_viewport + refresh_scroll_bgs при смене темы).
- В тёмной теме проверять ВСЕ экраны глазами/рендером: нативные виджеты вперемешку с Fluent дают «белые пятна».
- QMessageBox/result-диалоги: Fluent окна + нативные диалоги ок, но Fluent-виджеты внутрь нативных диалогов НЕ класть.
- Осторожно с .replace() в shell-скриптах: PowerShell, никакого `&&` (только `;`), grep/head/tail отсутствуют.
- QSettings пишет в реестр HKCU — тесты не должны менять пользовательские ключи молча (либо сохраняй/восстанавливай).
- run_app.bat/start.bat — ТОЛЬКО ASCII-символы! Кириллица в bat ломает cmd (команда разваливается на куски).
- pyproject/requirements: добавлять зависимости в оба файла (python-docx уже добавлен).
- Миграции делать идемпотентными (проверять наличие колонок/таблиц) — тест test_migration_makes_backup это ловит.
